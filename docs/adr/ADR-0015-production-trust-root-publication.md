# ADR-0015 — Production trust-root publication

## Status

Accepted for R14 implementation.

## Decision

HOWEDO will use TUF as the trust-root distribution and rotation substrate and will not invent a TUF-like repository or PKI. R14 adds a content-addressed publication policy and manifest that verify the complete public TUF root history with python-tuf.

The reference production policy requires at least three root keys with threshold two, consistent snapshots, disjoint top-level role key IDs, HTTPS publication endpoints, and a minimum remaining root validity window. These are HOWEDO reference production requirements, not claims that TUF universally mandates those exact values.

## Security boundary

The publication verifier proves that the supplied public root history is internally valid and threshold-signed according to TUF, and that the current root satisfies the selected HOWEDO publication policy. It does not prove where private keys were stored, who physically controlled them, or whether an offline ceremony was performed correctly. Those claims require separate operational evidence.

No production private key may be committed to GitHub, uploaded to CASER, placed in GitHub Actions secrets, or generated by the normal R14 CI path.

## Consequences

Consumers can pin a bootstrap root plus a publication manifest through an independent channel and later rely on R13 for authenticated target updates and sequential root rotation. All released root versions remain publication artifacts so outdated clients can traverse the full trust chain.
